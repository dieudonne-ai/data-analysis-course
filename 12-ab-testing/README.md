# Module 12 — A/B Testing (bonus)

An **A/B test** randomly splits users into **A (control)** and **B (variant)** and compares one metric.
Because assignment is random, a difference can be attributed to the change (causation, not just correlation).
Data: `data/ab_test.csv` (4000 visitors, generated by [`examples/make_data.py`](examples/make_data.py)).
Workflow diagram: [`diagrams/workflow.pdf`](diagrams/workflow.pdf)

## 1. Compare conversion rates
```python
g = df.groupby("group")["converted"].agg(n="size", conversions="sum", rate="mean")
```
| Group | Visitors | Conversions | Rate |
|-------|---------|-------------|------|
| A | 2000 | 213 | 10.65% |
| B | 2000 | 245 | 12.25% |

Lift: **+1.6 points** (+15% relative). Looks good, but is it real or luck?
Diagram: [`diagrams/conversion_ci.pdf`](diagrams/conversion_ci.pdf)

## 2. Two-proportion z-test
Pool both groups, compute the standard error, then `z = diff / se`.
Here **z = 1.59, p = 0.112** → above 0.05, so we **cannot** claim B is better.
The 95% CI for the lift is **[−0.4, +3.6] points**: it includes 0.
Diagram: [`diagrams/z_test.pdf`](diagrams/z_test.pdf)

## 3. Power and sample size
"Not significant" ≠ "no effect": the test may simply be too small. To detect 10% → 12.5% with
80% power at α = 5% we need **~2504 visitors per group**; we had 2000. Plan the size *before* the test.
Diagram: [`diagrams/power_curve.pdf`](diagrams/power_curve.pdf)

## 4. Common pitfalls
- **Peeking**: stopping as soon as p < 0.05 inflates false positives. Fix the duration in advance.
- **Many metrics**: test 20 metrics and one will look significant by chance. Pick one primary metric.
- **Non-random split** (e.g. A = morning, B = evening) breaks the causal claim.
- **Statistical vs practical significance**: a tiny lift can be significant with huge samples but not worth shipping.
